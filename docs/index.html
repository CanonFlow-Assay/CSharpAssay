THE BUSINESS CASE

Less review entropy. More trustworthy change.

CSharpAssay turns a small set of functional-first C# expectations into visible engineering controls. It does not grade taste; it narrows ambiguity where a machine can prove something useful.

⌘

01

Give reviewers a shared contract

Core and shell boundaries, null policy, immutable carriers, suppressions, and required release evidence become explicit—not tribal knowledge buried in comments.

  • Reviewable policy changes
  • Named enforcement owners

02

Make AI work inside guardrails

An agent gets a bounded shape, real commands, prohibited shortcuts, and stop conditions. It can move quickly without declaring its own work correct.

ONE NARROW PROMISE

Prove the selected contract—or say exactly why you cannot.

A clean result means the admitted rules and required evidence completed for the reviewed scope. It never silently expands into a claim about the whole application.

CSharpAssay is

  • A Roslyn analyzer and CLI
  • A functional-first policy gate
  • An evidence completeness check
  • A staged adoption tool

CSharpAssay is not

  • An OOP-to-functional converter
  • A security or quality score
  • A replacement for tests
  • A business-correctness proof

FUNCTIONAL C# SHAPE v0.1

Pure decisions in the center. Effects at the edge.

Shape v0.1 is a normative construction contract for a hand-built reference—not a CLI profile, template package, or universal architecture law.

PURE CORE Domain Values · decisions · invariants
←
CORE ORCHESTRATION Application Workflows · owned ports
dependency boundary
IMPERATIVE SHELL Infrastructure Storage · network · clocks
COMPOSITION SHELL API Transport · mapping · DI

Dependencies point inward. External representations cross the boundary once.

01

Make invalid state difficult to construct

Validated values expose factories that return explicit failure. Accepted aggregates come only from reviewed decision paths.

02

Model outcomes as data

Result<TValue,TError> and Option<T> are closed, non-null representations with both cases handled explicitly.

03

Pass effects through ports

Application orchestration owns effect contracts. Infrastructure implements them. Domain decisions receive every input directly.

04

Translate once at the edge

API and infrastructure may use ordinary OOP and frameworks, provided mutable and transport details do not leak inward.

HONEST RELEASE AUTHORITY

Pass is only one of four outcomes.

Most tools optimize for a green check. CSharpAssay optimizes for an honest answer—even when the honest answer is that the evidence is incomplete.

✓

Pass

The selected contract completed with all required evidence and no blocking finding.

exit 0
×

Fail

The evidence completed and proved at least one admitted blocking violation.

exit 1
?

Inconclusive

A required project, framework, rule, policy, compiler, or test fact is missing.

exit 2
!

ToolFailure

The toolchain or qualified evidence reporter failed; no release claim is made.

exit 3

START SMALL

Pin both packages to the same version. Begin with observation, install the analyzer only in reviewed core projects, and promote verify after the evidence is understood.

TWO-STAGE ADOPTION

Observe with check. Release with verify.

check is provisional and does not run configured release tests. verify executes the qualified evidence path and is the only authoritative command.

Installation & rollback → Staged adoption → 
# Provisional observation
dotnet tool run cs-assay check MySolution.slnx \
  --policy .csassay.json \
  --json artifacts/check.json

# Authoritative release decision
dotnet tool run cs-assay verify MySolution.slnx \
  --policy .csassay.json \
  --json artifacts/verify.json \
  --sarif artifacts/verify.sarif \
  --html artifacts/verify.html
  • .NET SDK 10.0.301 lane
  • .csproj, .sln, or .slnx
  • xUnit v3 + Microsoft Testing Platform for required-test evidence

THE EDGE OF THE CLAIM

Know what the green check does not mean.

Trust comes from being specific about the boundary. A CSharpAssay Pass is strong evidence for a small declared contract—not a universal certificate for the software.

Read before gating CI →
01

No business correctness guarantee. Product-owner tests and review still own intent.

02

No general security analysis. Use dedicated security tooling and threat modeling.

03

No architecture proof. Shape relies on tests and review outside admitted rules.

04

No unattended application rewrite. Automatic repair remains deliberately narrow.

05

No universal test runner. Required-test evidence is currently qualified for xUnit v3 on Microsoft Testing Platform.

06

No EF, messaging, concurrency, or performance qualification. Those need separate contracts and evidence.
