# CSAN0003 — Core source introduces a null value

Status: Admitted. Effective severity follows the shared core/shell/default policy.

## What caused the finding, and why it matters

An explicit null literal or a reference-typed default is used as data in the
analyzed scope. The caller must discover whether absence means missing input,
not found, failure or an invalid state, often far from where it originated.

## Before

```csharp
#nullable enable
internal static class Lookup
{
    internal static string? Find() => null;
}
```

## After

```csharp
public sealed record MissingName;
public sealed record FoundName(string Value);
public readonly union NameResult(MissingName, FoundName);
internal static class Lookup
{
    internal static NameResult Find() => new MissingName();
}
```

## Inspection and limits

The rule inspects Roslyn null-literal/default operations. Null constant patterns
that recognize input are allowed; implicit optional arguments are not source
introductions. It does not prove that a union is never default/null-backed, that
a FoundName is valid, or that an external API never returns null. Validate domain
boundaries and default union contents explicitly. Native-union exhaustiveness is
the compiler's responsibility; these declarations require the pinned preview SDK.

## Framework boundary

A transport/interop shell can receive nullable data, check it and map missing
input into an explicit core outcome. Do not move business behavior into shell to
escape findings. A null check preserves evidence; `!` does not validate input.

## Code fix and compatibility

No automatic fix. Select the domain meaning of absence with its owner. Changing
return types changes callers and serialization contracts; compile and test them.

## Evidence and grants

Executable specimens: `specimens/Native.Good/CSAN0003/` and
`specimens/Native.Bad/CSAN0003/`; these native examples compile in focused tests.
No blanket exemption is available; authorized grants remain fingerprint-specific.
