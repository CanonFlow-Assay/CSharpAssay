# CSAP0001 — A suppression lacks valid authorization

Status: Admitted. Integrity errors remain blocking, including in declared shells.

## What caused the finding, and why it matters

A CSharpAssay pragma/SuppressMessage, blanket suppression or invalid policy/build
setting bypasses the declared checks without the required matching authorization.
A warning disappearing is not evidence that the underlying problem was addressed.

## Before

```csharp
#pragma warning disable CSAI0001
public sealed record Expense
{
    public decimal Total { get; set; }
}
#pragma warning restore CSAI0001
```

## After

```csharp
public sealed record Expense
{
    public decimal Total { get; init; }
}
```

## Inspection and limits

The analyzer inspects CSharpAssay suppression syntax and shared policy grants;
its existing build/editor integrity guards also reject supported bypass attempts.
Compiler and other tools' suppressions are outside this targeted rule. An owner
string in policy is declared ownership, not authenticated human approval. The
rule cannot protect a host that removes the analyzer or controls all enforcement.

## Framework boundary

Declare genuine framework mutation/nullable contracts as shell responsibility;
keep business decisions in the core. Shell scope cannot suppress this integrity
rule. Never widen scope, remove tests or add grants automatically to get green.

## Code fix and compatibility

No automatic fix. The example removes the unauthorized pragma and the mutable
setter; review setter callers as described in CSAI0001. If a finding genuinely
needs an exception, use the existing exact fingerprint, owner, concrete reason
and expiry grant process. CSAP0001 itself cannot receive a grant. Expiry and
integrity checks remain in force; no second ignore or false-positive store exists.

## Evidence and grants

Executable specimens: `specimens/Native.Good/CSAP0001/` and

Fingerprint v1 includes position/message: editing source can change identity.
Do not silently transfer a prior grant to a different finding.
