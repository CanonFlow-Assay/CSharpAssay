# CSAI0001 — A public record property can be reassigned

Status: Admitted. Effective severity follows the shared core/shell/default policy.

## What caused the finding, and why it matters

A public property on a record exposes a public `set` accessor rather than
`init`. A caller can change it after creation, so code sharing the record may
observe different values without an explicit new value or transition.

## Before

```csharp
public sealed record Expense
{
    public decimal Total { get; set; }
}
```

## After

```csharp
public sealed record Expense
{
    public decimal Total { get; init; }
}
```

## Inspection and limits

The rule inspects property/containing-type symbols, the record shape and public
setter accessibility. Ordinary mutable classes are outside this restricted rule.
`init` prevents later property assignment; it does not freeze referenced objects.
An init-only `List<string>` can still be changed through the list reference.
A record is not proof that its entire object graph is immutable. CSAI0002 checks
selected collection types separately; neither rule proves business correctness.

## Code fix and compatibility

The explicit IDE action **Use init accessor** proposes the restricted
set-to-init auto-property edit. It declines setters with bodies. Preview it:
post-construction assignments, interfaces, serializers, binding and persistence
contracts may break. It does not migrate callers or preserve behavior by proof.
Run the affected builds/tests; no unattended CLI fix is provided.
