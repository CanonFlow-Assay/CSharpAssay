# CSAI0002 — A record exposes a mutable collection

Status: Admitted. Effective severity follows the shared core/shell/default policy.

## What caused the finding, and why it matters

A public record property exposes an array or a known mutable collection.
Changing elements through a shared collection reference can change a record's
observed contents even when its property cannot be reassigned.

## Before

```csharp
using System.Collections.Generic;
public sealed record Batch(List<string> Items);
```

## After

```csharp
using System.Collections.Immutable;
public sealed record Batch(ImmutableArray<string> Items);
```

## Inspection and limits

The rule checks public record property type metadata: arrays, ArrayList,
Hashtable, ICollection/IList/IDictionary, their generic forms, List, Dictionary,
HashSet, Collection and ObservableCollection. Custom types are not guessed to be
immutable or mutable. An immutable container can still contain mutable objects;
this is not recursive object-graph validation. Default collection values and
business invariants need their own validation/tests. An interface with fewer
mutation methods does not establish ownership of the underlying collection.

## Framework boundary

A framework collection contract may belong in a declared serializer/ORM shell.
Convert/copy deliberately when crossing into the core. Do not relocate business
rules or grant exemptions simply to pass. Shell observations remain visible.

## Code fix and compatibility

No code fix is supplied. Choose ownership, copying, allocation, ordering and
serialization semantics with the caller. The example changes the contract;
update constructors and serializers and execute the relevant tests.
